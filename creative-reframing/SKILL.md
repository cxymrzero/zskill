# Creative Reframing

用三个正交的思维模型制造视角差异，再把差异收敛成可验证的行动。模型不是答案；模型必须改变问题的结构或候选行动。

## 1. Frame

先建立上下文地图。阅读 [`references/context-gathering.md`](references/context-gathering.md)，从用户输入和当前可访问资料中提取：

- 想改变的结果与可观察的成功标准；
- 问题发生的具体实例、频率或基线；
- 产生结果的当前流程或机制；
- 受影响者、决策者与用户能改变的范围；
- 约束、不可触碰项和已经尝试的方法。

默认进入 **diagnostic 模式**。识别一个最高影响未知项：它的不同答案会改变所选模型、干预位置或方案可行性。一次只问一个问题，等待回答后更新上下文地图，再决定是否继续追问。优先提问具体事实和最近实例，不要求用户先解释根因；能从代码库或其他可访问资料查到的信息自行查找。

只有用户明确要求“先给思路”“快速发散”或“不追问”时，才进入 **rapid 模式**：列出关键假设并直接继续。用户不知道或不愿回答时，把未知项转成待验证假设，不要卡住流程。

当以下信息均已获得、被用户确认为未知，或在 rapid 模式中被显式假设时，本步完成：

1. 目标和成功标准；
2. 至少一个具体实例或基线；
3. 当前机制及关键参与者；
4. 可改变范围与重要约束。

最后写出一句“在这些约束下，怎样改变这个结果”的工作陈述，并区分观察到的事实、用户判断和待验证假设。

## 2. Select

阅读 [`references/model-selection.md`](references/model-selection.md)，再从 [`references/models.md`](references/models.md) 选三个模型。三个模型必须来自不同功能族，且分别承担：

1. 暴露假设或矛盾；
2. 扩展候选空间；
3. 检查系统后果或行动风险。

向用户用一句话说明每个模型为什么适合当前问题。三个模型职责互不重复时，本步完成。

## 3. Reframe

对每个模型依次给出：

- **模型看到什么**：此前被忽略的结构；
- **问题改写**：该模型会提出的、更有生成力的问题；
- **由此产生的方案**：至少一个只有采用该视角才自然出现的候选方案。

若换掉模型名称后内容仍然成立，说明重构无效；重新应用该模型。三个重构都实质不同后，本步完成。

## 4. Synthesize

把候选方案整理为：

- 可以组合的部分；
- 彼此冲突的取舍；
- 依赖事实验证的假设。

不要用平均化折中抹掉模型间有价值的冲突。形成至少三个可区分的候选方案后，本步完成。

## 5. Act

推荐一个下一步行动实验，包含：

- 具体动作；
- 成本或时间盒；
- 要验证的关键假设；
- 成功、失败或停止信号。

最终输出必须包含上下文依据与关键假设、一句工作陈述、三个实质不同的重构视角、至少三个候选方案，以及一个用户可以立即启动的行动实验；五项齐全才算完成。
