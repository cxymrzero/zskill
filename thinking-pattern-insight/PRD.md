# Thinking Pattern Insight PRD

## 目标

当前版本：V1 题目映射校准版。V0 报告保留为探索性样例，不作为标准化结果。

通过一系列基于真实情境的问题，帮助用户本人理解自己的信息处理、决策和行动偏好，并生成一份自然语言优先的个人思维模式 HTML 报告。

MBTI 和荣格八维是解释语言，不是诊断工具。产品目标是促进自我观察，而不是给用户贴上固定标签。

## MVP 范围

- 单次会话探索；
- 仅支持用户本人参与访谈和查看自己的报告；
- 一次只问一个具体情景选择题；
- 根据当前不确定性自适应选择下一道情景题；
- 记录支持证据、相反证据、证据类型和置信度；
- 区分偏好证据、策略证据和情境证据；
- 输出八维雷达图；
- 输出 MBTI 四个维度的中心偏好图；
- 输出 MBTI 类型候选，而非强制唯一类型；
- 生成无外部依赖的独立 HTML 文件；
- 支持术语展开学习区；
- 支持用户选择“不确定”、跳过、纠正和停止。

## 非目标

- 心理疾病、人格障碍、智力或职业适配诊断；
- 招聘、淘汰、医疗或重大关系决策；
- 仅通过固定题库计算四字母类型；
- 第一版的跨会话长期人格追踪；
- 替他人测试、评价他人或根据第三方描述生成个人画像；
- 将功能分数解释为能力值。

## 访谈协议

- 参考 `grill-me` 的渐进式访谈方式，一次只问一个问题；
- 推荐问题数为 18 个，绝对上限为 24 个；
- 上限包含同意确认后的澄清、追问和校准问题；
- 用户本人必须参与访谈；
- 任何时候都可以跳过问题、暂停或停止；
- 至少从一个真实场景开始，不接受纯抽象自评作为唯一依据；
- 在形成结论前展示暂定观察并允许用户校准；
- 证据不足时生成低置信度结果，而不是强行分类；
- 达到问题上限后停止提问，保留未知项并生成报告。

## 用户体验要求

用户即使不了解 MBTI，也应能读懂报告主体。报告先展示行为观察，再展示图形，再提供原始术语和分析依据。

报告必须同时满足：

- 自然语言清晰、简明、可扫描；
- `Ne`、`Ni`、`Ti` 等原始维度可见；
- 八维雷达图有文本替代；
- MBTI 四轴有方向、强度和中间状态；
- 图表不单独承担结论；
- 每个重要结论有支持证据和不确定性；
- HTML 可直接打开、打印和保存。

## 完成标准

- 至少使用多个具体场景交叉验证；
- 能处理矛盾答案、低信息量和用户反驳；
- 能区分自然偏好与工作训练；
- 每道诊断题只对应一个主要功能轴；
- `Ti/Te`、`Fi/Fe`、`Ni/Ne`、`Si/Se` 均有跨场景的纯维度题；
- 不把执行、协调、应变和信息搜集能力直接当成功能偏好；
- 不把轻微偏好强行转换成确定类型；
- 不使用外部网络资源生成报告；
- 敏感表达触发安全边界；
- 报告结构在桌面和移动端均可阅读。
