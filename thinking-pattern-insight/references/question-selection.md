# Question Selection

## 目标

每次只选择一个最能减少当前不确定性的题目。题库不是固定问卷，问题顺序由场景覆盖、证据质量和竞争性假设共同决定。提问方式遵循 [`grill-me-protocol.md`](grill-me-protocol.md)，渐进展开并控制总题数。

## 预算检查

选择问题前先检查 `questionCount`：

- `0-17`：可以继续探索；
- `18-23`：只选择能改变主要结论的问题，否则进入校准；
- `24`：停止提问，生成报告或低置信度结果。

## 选择优先级

按以下顺序选择下一题：

1. 安全或同意问题；
2. 当前场景缺少具体事实；
3. 会改变主要结论的高影响不确定性；
4. 缺少竞争性解释的维度；
5. 缺少第二个场景的交叉验证；
6. 用户主动提出的疑问。

## 不确定性表示

使用明确的键名记录待区分内容：

```text
Ni_vs_Ne
Si_vs_Se
Ti_vs_Te
Fi_vs_Fe
I_vs_E
J_vs_P
preference_vs_role
low_pressure_vs_stress
```

## 决策规则

- `uncertainties` 为空时，优先切换到尚未覆盖的场景；
- 某一维连续回答两题后仍不清楚，切换到不同场景或记录 unknown；
- 若两个候选解释得到相同支持，优先问能产生不同现实行为的问题；
- 若回答只表达观点，没有事件，优先追问“最近一次是什么时候”；
- 若回答显示明显反例，不继续收集支持同一结论的问题，先记录反证；
- 若用户回答过短或表示疲劳，降低问题数量并进入校准；
- 至少两个场景有有效证据后，才能进入假设和校准阶段。

## 选择记录

每次选择问题时，内部保留一句原因，不需要展示给用户：

```json
{
  "questionId": "perception-01",
  "reason": "当前 Ni 与 Ne 的支持度接近，且尚未有具体例子区分收敛与发散",
  "expectedInformation": "用户在已有合理方向后是继续扩展，还是开始推进"
}
```

## 不应发生

- 为了凑齐八个功能而机械提问；
- 为了达到推荐题数而继续提问；
- 连续询问用户“你更像 A 还是 B”；
- 把用户不确定当成某一侧的证据；
- 只收集支持当前类型的回答；
- 在没有第二场景或校准前给出确定类型。
