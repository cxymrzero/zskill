# Assessment Model

## 证据优先

每个回答先记录行为事实，再记录解释信号。不得直接把用户自评的 MBTI 字母当作证据。必须区分“偏好证据”和“策略证据”：工作训练、角色要求、成熟的执行能力和被动适应变化，不能直接当成功能偏好。

```json
{
  "questionId": "decision-03",
  "context": "工作决策",
  "answerSummary": "先列出限制条件，再比较方案的长期后果",
  "signals": [
    { "code": "Te", "kind": "strategy", "direction": "support", "strength": "medium" },
    { "code": "Ni", "kind": "preference", "direction": "support", "strength": "medium" }
  ],
  "counterSignals": [],
  "confidence": "medium"
}
```

## 支持度

支持度表示当前回答对某种思维模式的支持程度，不表示能力或人格价值。V1 还必须遵守：

- 每道核心题只设置一个主要区分维度；
- 每个选项最多有一个 `primarySignal`，其他内容记录为情境标签；
- 单题信号不能直接形成“高分”；
- 同一信号至少在两个不同场景中重复出现，才可从弱支持提升为中等支持；
- 角色、训练、压力和被动适应行为默认标记为 `strategy` 或 `contextual`；
- 只有跨场景、低提示性的第一反应，才适合作为 `preference` 证据；
- 题目选项必须有一个清晰的 `primarySignal`，不得把“目标、效率、关系、现场”混在同一个功能标签里。

建议内部使用 0-100 的连续值，用户可见时使用：

- 0-20：较少出现；
- 21-40：偶尔出现；
- 41-60：情境依赖；
- 61-80：较明显；
- 81-100：很明显。

证据不足时使用 `unknown`，不能用低分代替未知。

## V1 计分流程

1. `context-only` 和 `contextual-strategy` 只用于选择下一题，不进入功能分数。
2. `preference` 证据单题记为弱支持；同一功能在第二个不同场景重复出现后，才提升为中等支持。
3. `strategy` 证据只用于报告中的“行为能力/应对方式”，不直接提高功能支持度。
4. 并列双选每个信号按半权重记录；有序双选时第一动作权重高于第二动作，但两者都不能单独形成高支持。
5. `unknown`、都不像和用户明确反驳的信号不计正分，并记录为反证或未知。
6. 最终显示相对支持度和证据等级，不把未经标准化的数值包装成测量结果。

## 竞争性解释

每个主要结论至少保留一个替代解释。例如：

- 看起来像 `Ni`，也可能是用户的职业训练；
- 看起来像 `Te`，也可能是当前承担管理职责；
- 看起来像 `Se`，也可能只是用户能够适应突发变化；
- 看起来像 `Si`，也可能只是用户在做稳健的信息搜集；
- 看起来像 `I`，也可能是对陌生环境的谨慎。

## 校准

在最终报告前向用户展示暂定观察，并允许用户指出：

- 观察是否准确；
- 哪些场景不符合；
- 哪些表现是被环境要求出来的；
- 是否存在重要例外。

用户反馈应修改证据和置信度，而不是被解释成用户没有“认识真实的自己”。官方或其他成熟测试结果只能作为校准参考，不能被当作绝对真值；当结果冲突时，应回到具体题目和证据类型检查映射。
