# Sample Interview

这是一个验证渐进式情景选择流程的示例，不是标准答案。

## Consent

**Agent：** 这次探索只用于帮助你观察自己的思维偏好，不是心理诊断，也不会替你做重大决定。报告会包含 MBTI 和荣格八维作为解释语言，但结果可能不确定。接下来会通过不超过 24 道情景选择题逐步了解你，你愿意开始吗？

**User：** 愿意。

状态：`consent -> context`

## Context question

**Agent：**

场景：你接到一个信息不完整、但需要尽快决定的任务。

问题：你最可能先做什么？

- A. 先列出已知事实、限制条件和缺失信息。
- B. 先想这个任务可能发展成哪些方向。
- C. 先判断哪个选择最符合自己真正重视的原则。
- D. 先找相关的人讨论，看看大家最在意什么。

推荐回答：选择最接近你第一反应的一项；如果都不像，可以选择“不确定”。

**User：** A。

内部记录：

```json
{
  "questionId": "context-01",
  "answer": "A",
  "signals": ["Si", "Te"],
  "confidence": "low"
}
```

状态：`context -> evidence_collection`

## Adaptive question 1

当前不确定性：`Ni_vs_Ne`、`Si_vs_Se`

选择理由：第一题只能说明用户先整理条件，尚不足以区分其后续是寻找主线、扩展可能，还是依赖现场事实。

**Agent：**

场景：你需要解决一个没有标准答案的复杂问题。

问题：哪种做法最像你的第一反应？

- A. 先找出一个最能解释整体情况的主线。
- B. 先从一个想法扩展出多个可能方案。
- C. 先查找过去类似的案例和可靠做法。
- D. 先观察当前现场有哪些事实和可利用的机会。

推荐回答：只选择最接近你第一反应的一项，不需要解释原因。

**User：** B。

内部记录：

```json
{
  "questionId": "perception-01",
  "answer": "B",
  "signals": ["Ne"],
  "counterSignals": ["Ni"],
  "uncertainties": ["Ti_vs_Te", "I_vs_E", "preference_vs_role"],
  "confidence": "medium"
}
```

## Adaptive question 2

切换到决策维度并建立第二个场景。

**Agent：**

场景：两个方案都能解决问题，但各有取舍。

问题：你最可能优先比较什么？

- A. 哪个方案的概念和推理最严密。
- B. 哪个方案最容易达成目标并有效落地。
- C. 哪个方案最符合自己的价值和底线。
- D. 哪个方案最容易被相关的人理解和接受。

推荐回答：选择你通常最先关注的标准，而不是事后认为“应该”关注的标准。

**User：** B。

内部记录：

```json
{
  "questionId": "decision-01",
  "answer": "B",
  "signals": ["Te"],
  "confidence": "medium"
}
```

## Calibration

已获得三个选择，其中两个维度出现了可解释信号。继续选择题，直到达到足够交叉证据，或用户主动结束。校准也保持选择形式，不要求开放叙述。

**Agent：**

场景：刚才描述的做法发生在工作中，但你现在想判断它是不是稳定偏好。

问题：在没有工作要求时，哪种情况更接近你？

- A. 私下也基本如此，只是工作中更明显。
- B. 私下会明显更随性，不太提前计划。
- C. 私下会更重视自己的感受和价值判断。
- D. 私下会更依赖当下兴趣和现场变化。

推荐回答：选择最接近你大多数私人场景的一项；如果不同生活领域差异很大，可以选择“不确定”。

## Report decision

报告必须：

- 只使用情景选择产生的证据；
- 说明当前覆盖了哪些场景；
- 将未充分区分的功能标为“暂不确定”；
- 不把工作选择直接推广到私人生活；
- 保留竞争性类型和场景依赖；
- 根据实际题数生成置信度。
